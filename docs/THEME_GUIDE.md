# 색은 자유롭게 바꾸세요

`content/theme.json` 한 파일에서 밝은 화면(`light`)과 어두운 화면(`dark`)의 색을 고릅니다. 기본 보라·산호색을 유지할 의무는 없습니다. 청록·파랑·주황·무채색 등 원하는 계열로 바꿀 수 있습니다.

에이전트에 이렇게 요청할 수 있습니다.

```text
전체 레이아웃과 아트 문법은 유지해 줘.
강조색은 청록, 밝은 화면은 따뜻한 흰색, 어두운 화면은 짙은 남색으로 바꿔 줘.
그림의 빛 팔레트도 같은 계열로 맞추고 두 테마의 글자와 그림이 선명한지 확인해 줘.
content/theme.json에서 수정하고 기본 색을 강제하지 마.
```

## 각 토큰의 역할

| 토큰 | 바꾸는 것 |
|---|---|
| `paper` | 소개·레일 등 기본 바탕 |
| `ink` | 기본 글자 |
| `mutedInk` | 보조 설명 |
| `subtleInk` | 더 약한 라벨·표식 |
| `line` | 얇은 구분선 |
| `wash` | 옅은 면·선택 보조 배경 |
| `stage` | 프로젝트 그림과 본문의 바탕 |
| `stageInk` | 그림 바탕 위의 글자·기본 윤곽 |
| `accent` | 제목의 강조 단어와 작은 핵심 표식 |
| `signalPalette` | 그림의 밝기를 색으로 옮기는 팔레트 |

값은 `#007a64` 같은 6자리 또는 `#0a7` 같은 3자리 HEX 색입니다. `light`와 `dark` 모두 같은 토큰이 필요합니다. 둘을 같은 색으로 만들 필요는 없습니다.

## 그림 팔레트

- `light.signalPalette`: 6개 색을 약한 신호에서 강한 신호 순서로 적습니다. 밝은 바탕에서는 강한 신호의 윤곽이 충분히 짙게 읽히도록 조합하는 편이 좋습니다.
- `dark.signalPalette`: 4개 색을 약한 신호에서 강한 신호 순서로 적습니다. 어두운 바탕에서는 강한 부분이 더 밝고 또렷하게 읽히도록 조합합니다.
- 색상 계열은 자유입니다. 역할·밝기의 순서와 대상의 가독성이 중요합니다. 라벨과 버튼 전체를 팔레트 그라디언트로 칠하지 않습니다.

CSS 변수와 WebGL 셰이더의 색은 이 파일에서 함께 생성됩니다. CSS와 셰이더의 색 숫자를 별도로 고칠 필요가 없습니다. `src/lib/theme.ts`와 `scripts/theme.mjs`가 연결합니다.

## 바꾼 뒤 확인

```sh
npm run check-art
npm test
npm run build
npm run check-types
```

정적 빌드이므로 색을 바꾼 뒤에는 다시 빌드·배포해야 사이트에 반영됩니다. GitHub Pages에서는 `main`에 변경을 올리면 워크플로가 다시 빌드합니다.

검사는 HEX 형식·필수 토큰·팔레트 개수·런타임 연결을 확인합니다. 특정 색을 고르라고 강제하지 않으며, 명암이나 아름다움까지 자동 보증하지 않습니다. 실제 밝음/어두움에서 글자·얇은 선·그림·강조·선택 상태를 확인하세요. 색을 바꾸었더니 대상이 안 보이면 기본 색을 되돌리는 대신 선택한 계열 안에서 명암·밀도·밝기를 조정합니다.

새로운 시각 요소도 역할에 맞는 기존 토큰을 먼저 사용합니다. 새 색 역할이 필요하면 토큰·검증·문서를 함께 확장합니다. 컴포넌트별로 임의의 색을 중복 정의해 사용자의 테마 선택을 무시하지 않습니다.
