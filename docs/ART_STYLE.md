# 아트 스타일의 고정 원칙

## 1. 이 스타일이 지향하는 것

**한눈에 의미가 읽히면서, 조형 자체가 충분히 미려하고 인상적인 포트폴리오.** 정확해도 투박한 그림, 화려해도 무엇을 했는지 모르는 그림은 모두 미완성이다.

기존 제작 과정의 사용자 요청·수락·기각과 실제 렌더링 코드를 대조해 만든 기준이다. 개인의 프로젝트·수치·내부 자료는 포함하지 않는다. 새 에이전트는 이 기준을 읽고 제작하며, 사용자에게 미감의 처음부터 끝까지를 다시 설명하게 하지 않는다.

완료 조건은 여섯 가지다: ① 주장과 인과가 맞다 ② 대상과 차이가 즉시 읽힌다 ③ 실루엣·밀도·비율·명암·여백이 아름답다 ④ 같은 대상은 전역에서 같다 ⑤ 움직임이 사건과 관계를 설명한다 ⑥ 실제 노트북·절반 창·휴대폰에서 충분히 크고 선명하다. 컴파일·내용 정확성만으로 완료를 선언하지 않는다.

## 2. 아트 변경 권한과 사용자 판정

- 사용자의 현재 명시적 지시가 최우선이다. 이 문서를 이유로 사용자 요청을 거절하거나 별도 승인 절차를 만들지 않는다.
- 일반적인 내용 교체는 이 방향 안에서 한다. 매번 새 테마를 제안하거나 취향을 다시 묻지 않는다.
- 스타일 변경을 요청받았다면 바꿀 축·유지할 축·실제 비교 장면을 먼저 정리한다. 에이전트 취향으로 기준을 완화하지 않는다.
- 좋아한 장면은 지정한 부분만 고친다. "좌우만"을 전체 조형·등장 순서·동작 재설계로 확대하지 않는다.
- 제안·구현·검증·사용자 수락을 구분한다. 커밋·배포·"일단 정리"는 모든 그림의 미감 수락이 아니다.
- 실패한 표현과 아직 판정하지 않은 표현을 확정 스타일로 옮기지 않는다. 다만 특정 장면의 기각을 모든 미래 장면의 영구 금지로 확대하지 않는다.

## 3. 독자가 먼저, 그림이 먼저

여러 포트폴리오를 짧게 훑는 사람이 더 읽고 싶게 만든다. 프로젝트의 목적과 작성자의 기여가 첫 화면에서 드러나야 한다. 기술명은 보이는데 판단과 기여가 긴 글 속에 숨으면 실패다.

정보 순서: 한 문장 → 전체 한 장 → 핵심 두세 가지 → 자세한 근거. 그림과 글로 모두 설명할 수 있으면 그림을 우선한다. 긴 과정은 상세로 보내되 필요한 근거는 제자리에 보인다. 모호한 그림을 설명 문단으로 덮지 않는다.

**화려함을 줄여서 복잡함을 해결하지 않는다.** 큰 조형 하나와 명확한 사건으로 정돈한다. 의미 없는 입자·회전·번짐을 늘려 화려함을 대신하지도 않는다.

## 4. 한 장의 구도: 주인공 하나, 사건 하나

- 먼저 이 그림의 주장을 한 문장으로 쓴다. 도형·카메라·빛·시간을 모두 그 주장에 맞춘다.
- 전체 구조를 매번 반복하고 변경점만 구석에 작게 두지 않는다. 특정 판단의 장면은 그 부분으로 카메라를 가져오고 나머지는 조용한 문맥으로 남긴다.
- 주인공은 한 덩어리로 읽힌다. 작은 물체를 빈 공간에 흩어 놓거나 대상 사이에 긴 빈 통로를 남기지 않는다.
- 입력·처리기·출력의 비율과 밀도를 구별한다. 주인공이 너무 작거나 흐린 점으로만 보여 존재감이 없으면 실패다.
- 전후는 같은 대상·좌표계·시점에서 비교한다. 옅은 이전 윤곽을 남겨 정지 화면에서도 차이가 보이게 할 수 있다.
- 다른 역할·후보를 동일한 빈 사각형에 이름만 다르게 적지 않는다. 실제 차이는 실루엣·밀도·사건으로 드러낸다.
- 결과값은 그것이 속한 대상 가까이에 둔다. 무관한 모서리의 숫자 상자, 원근 때문에 대상 옆으로 어긋난 값은 금지한다.
- 배경 가이드·격자·바닥·프레임은 데이터보다 조용해야 한다. 복잡한 받침대가 주인공보다 밝으면 실패다.

## 5. 사실과 설명용 단순화

**사실을 크게 벗어나지 않으면서 이해를 돕는 그림을 우선한다.** 실제 구현의 모든 층·점·프레임을 원본 속도로 재생하는 것이 목적이 아니다.

허용: 반복 층 압축, 대표 샘플, 밀도 조절, 짧은 평활, 느린 설명 재생, 작은 구간의 시각적 확대, 주요 사건만 남김, 의미를 보존하는 상징화. 도형 크기가 실측 비율이 아니면 실측 그래프인 척하지 않는다. 실제 값·단위는 유지한다.

불가: 입력·출력 종류, 원인·결과·선후·미래 정보 사용, 포함 관계, 학습·실행 경계를 바꾸기. 없는 단계·모듈·수치·성능을 추가하기. 원신호를 추론 출력처럼 표시하기. 작은 차이를 큰 이득처럼 만들기. 불확실성을 확정 상태처럼 그리기.

추리고 평활한 부분은 제작 메모에 남긴다. 화면에는 오해를 막는 조건만 짧고 정확하게 적는다. 추상 장식은 장식으로 표시한다.

## 6. 세 가지 장면 문법

### A. 연속 신호와 공간: 빛

점·선·밀집된 분포가 가산광으로 하나의 형태를 만든다. 누적 밝기가 색으로 바뀐다. 곡선은 정돈된 가닥·다발·면의 윤곽으로 읽혀야 한다. 잔가닥과 지터가 주인공을 덮으면 실패다.

어두운 바탕: 남보라 → 자홍 → 주황 → 앰버. 밝은 바탕: 살구 → 산호 → 장미 → 자주 → 짙은 보라의 flare. 글자·버튼·모든 물체를 이 색으로 물들이지 않는다. 회색 플라스틱 띠, 네온 게이지, 의미 없는 은하·점구슬로 대체하지 않는다.

### B. 이미지·토큰·선택·모델 관계: 잉크와 원본 색

구조·모델·연결선·라벨은 테마 잉크다. 의미 있는 원본 이미지 조각과 그로부터 온 토큰은 원본 색을 유지할 수 있다. 바뀐 곳만 밀도·명암·위치·전후 윤곽으로 강조한다. 모든 부분에 신호 램프를 강제하지 않는다.

처리기는 얇은 고리와 정돈된 가닥처럼 실체가 있는 공통 조형으로 만든다. 의미 없는 검은 구·점 격자·세 장의 카드와 화살표로 끝내지 않는다. 입력이 변하고 표현이 따라 바뀌는 하나의 구조로 읽히게 한다. 밝은 화면은 잉크처럼, 어두운 화면은 빛처럼 읽힌다.

### C. 사람이 남긴 행위와 처리: 종이·표식

문서·필기·영수증·도장·장부처럼 행위와 결과를 직접 드러내는 사물을 쓸 수 있다. 필기와 확정 도장처럼 누가 무엇을 했는지 구별한다. 종이는 어두운 테마에서도 종이색을 유지하고 바탕 위의 글과 연결은 테마 잉크를 따른다.

내용에 맞을 때만 쓴다. 모든 장면을 연구 노트처럼 인장·메모·장부로 채우지 않는다. 과한 종이 텍스처와 빈티지 장식은 기본값이 아니다.

세 문법은 내용에 따라 고른다. 모든 프로젝트를 빛이나 종이로 똑같이 만들지 않는다. 바탕·타이포·선·심볼·정렬의 공통 기준으로 사이트를 묶는다.

## 7. 같은 대상은 같은 심볼

- 홈·상세·메뉴·다른 그림의 같은 대상은 한 함수 또는 자산에서 나온다. 심볼 목록에 뜻·원본 구현·불변 요소·상태 변화·사용 화면을 기록한다.
- 작은 심볼은 큰 장면의 축소판이 아니다. 가장 작은 표시 크기에서 알아보게 정리한 뒤 그 원본을 재사용한다.
- 두께·밀도·시점은 환경에 맞춰 조절해도 핵심 구성과 의미는 유지한다. 두 입력이 핵심인 구조를 예쁜 한 가닥으로 바꾸지 않는다.
- 원신호·처리기·추론 출력처럼 뜻이 다르면 심볼도 구분한다. 긴 캡션이 있어야만 뜻이 생기는 표식은 빼거나 다시 그린다.
- 스피커·화살표처럼 작은 실루엣이 중요한 도형을 억지로 점묘로 만들지 않는다. 같은 문법 안의 곡선·면도 허용한다.

## 8. 자유로운 색 토큰과 명암

**색상 선택은 자유다.** 아래 표는 초기 예시값이다. 사용자는 `content/theme.json`에서 배경·글자·선·강조색·그림의 팔레트를 원하는 계열로 바꿀 수 있다. 색을 바꾸어도 의미·심볼·선·명암·카메라의 표현 문법을 유지한다. [색 변경 안내](THEME_GUIDE.md)를 따른다.

| 역할 | 밝음 | 어두움 |
|---|---|---|
| `--paper` | `#ffffff` | `#151319` |
| `--ink` | `#171717` | `#e7e5eb` |
| `--ink-2` | `#626262` | `#b7b3bb` |
| `--ink-3` | `#989898` | `#6d6973` |
| `--line` | `#e3e3e3` | `#2c2830` |
| `--wash` | `#f3f3f3` | `#211d25` |
| `--stage` | `#fafafa` | `#110f15` |
| `--stage-ink` | `#232323` | `#e7e5eb` |
| `--signal` | `#c04466` | `#e36986` |

- 기본 어두운 중립색은 보랏빛 회색이다. 다른 계열도 허용한다. 새 장면의 바탕은 사용자가 정한 `stage`를 따르고 별도의 색을 중복 정의하지 않는다.
- 제목 강조는 사용자가 고른 `accent` 한 단색이다. 글자에 신호 그라디언트를 적용하지 않는다. 사용자 팔레트를 원본의 기본값으로 강제로 되돌리지 않는다.
- 먼저 실루엣·비율·밀도, 그다음 밝기·블룸이다. 주인공·문맥·가이드의 강도를 구별한다.
- 밝은 화면에서 핵심 윤곽을 흐린 점만으로 그리지 않는다. 선·밀도·실루엣으로 유지한다. 어두운 그림을 흰 바탕에 그대로 얹지 않는다.
- 어두운 화면에서 모든 선이 노랗게 타거나 화면을 보라 안개로 덮으면 실패다. 밝은 화면은 짧은 번짐과 또렷한 핵을 유지해 회색 얼룩을 줄인다.
- 바탕과 캔버스의 사각 경계가 보이면 실패다. 색·투명도·번짐 잘림까지 확인한다.
- 원근·겹침·거리 감쇠·약한 공간 입자로 깊이를 만든다. 반사 바닥·유리판·보케를 겹치는 것은 기본 미감이 아니다.

## 9. 선과 지시선

관계를 잇는 선은 수평·수직·45° 구간과 정돈된 둥근 꺾임을 사용한다. 데이터 선과 지시선은 같은 경로 문법, 다른 시각적 역할이다. 고리·파형·물체 자체의 곡면은 이 제약의 대상이 아니다.

데이터 선은 조금 굵고 진행하는 빛을 가질 수 있다. 지시선은 가늘고 조용하며 대상 위 점·라벨 옆 짧은 착지 구간을 갖는다. 대상과 글을 같은 카메라·같은 프레임에서 투영해 움직여도 떨어지지 않게 한다.

선이 글·대상·다른 선을 가로지르면 배치를 먼저 고친다. 원근이 만든 몇 px 차이를 지저분한 계단으로 만들지 않는다. 긴 빈 통로·허공의 끝점·불필요한 짧은 지시선을 없앤다. 구현값은 [ART_RECIPES.md](ART_RECIPES.md)를 따른다.

## 10. 움직임과 카메라

**카메라 이동·확대·축소·조립·변형을 금지하지 않는다.** 어디로 들어가는지, 무엇이 바뀌는지, 무엇과 같은 대상인지를 드러내는 연출은 적극 사용한다. 페이지마다 같은 줌·회전을 반복하는 장식은 피한다.

- 정지 상태에서 먼저 형태·배치를 완성하고, 움직임으로 인과·방향을 더한다.
- 전환 전후의 동일 대상은 화면 중심·크기·기울기를 맞춘다. 자식 부품으로 들어갈 때 그 부품을 향하고 돌아올 때 같은 자리에서 나온다. 없는 포함 관계를 만들지 않는다.
- 완료는 가능하면 준비·착지 신호로 결정한다. 느린 프레임에서 착지 전 바뀌는 고정 타이머를 피하고 실패 시 일반 전환으로 복귀한다.
- 이동 중 글자가 주인공과 겹치면 대상이 안정된 뒤 등장시킨다. 바뀌지 않는 축·문자·기준은 고정하고 바뀌는 대상만 이동시킨다.
- 한 번에 한 변화를 보여 준다. 여러 선택지가 동시에 우왕좌왕하지 않는다.
- 실제 사건의 순서는 유지하되 표시 수량·평활·재생 속도를 조절해 지터가 설명을 덮지 않게 한다.
- 포인터 시차는 부드럽고 프레임 속도에 독립적이다. 터치·키보드·움직임 줄이기에서도 정보·조작이 남는다.
- 보이지 않는 장면은 프레임·소리를 정지·음소거한다. 재방문과 같은 화면 위 상세 닫기를 구분하고 초기화 정책을 명시한다.
- 루프에서 이전 바퀴의 창·차분·입자·확정 상태를 새 바퀴에 섞지 않는다. 경계의 형태를 실제 움직임으로 확인한다.
- 자동 진행은 콘텐츠별 결정이다. 임의의 자동 프로젝트 이동을 추가하지 않는다. 자동 장면에는 읽을 체류 시간과 명확한 이동 수단을 둔다.

## 11. 레이아웃과 타이포그래피

- 넓은 화면은 왼쪽 레일·오른쪽 한 장면. 모바일·세로 창은 레일이 위로 접힌다. 제목·중복 문구 때문에 그림이 작아지지 않게 한다.
- 본문은 로컬 Pretendard Variable. 숫자·단위·짧은 영문 계측 라벨은 Geist Mono다. 한글·띄어쓰기·가운뎃점은 Pretendard 간격을 유지한다.
- 제목은 크기·굵기·자간·줄높이·줄바꿈을 함께 조절한다. 큰 글자로 밀어 넣지 않는다. 현재 범위: 제목 약 30~60px, 모바일 28~42px, 본문 14~17px, 보조 라벨 10~13px.
- 가는 잉크선으로 구분하고 검은 강조는 선택·시작·큰 경계에 쓴다. 대시보드 카드·채도 높은 칩·다중 테두리로 위계를 대신하지 않는다.
- 전환 중 그림 칸·조작 위치가 튀지 않는다. 휴대폰에서 돌아가기·현재 위치·이름 줄을 잃지 않는다.

## 13. 현재 구현과 확장 규칙 구별

현재 `orbit`, `layers`, `flow`, `none`은 추상 장식 예시다. `quantization`은 합성 지형으로 만든 설명용 비교 도식이며, 상세의 2D 심볼과 함께 견본으로 사용한다. 실제 모델의 측정값이나 작성자의 실적을 뜻하지 않는다. 의미 있는 프로젝트 도식의 완성형 설계나 사용자 미감 수락을 받은 원본 장면 전체의 복제본이 아니다.

포함된 것은 점광원 렌더러·세 장식 장면·사이트 레이아웃이다. 실제 데이터 도식, 종이 장면, 심볼 레지스트리, 연속 카메라는 이 규칙에 따라 필요한 프로젝트에 구현할 확장이다. 이미 구현되었다고 보고하지 않는다.

`npm run check-art`는 자유 색 토큰의 형식·런타임 연결, 폰트 범위, 필수 문서를 검사한다. 특정 색을 강제하지 않는다. 의미·미감·명암·동작은 자동 판정하지 않는다. [ART_REVIEW.md](ART_REVIEW.md)의 화면 검수가 별도로 필요하다.
