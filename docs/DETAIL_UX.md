# 상세 화면과 두 레일의 읽기 UX

카테고리 레일과 상세 목차 레일은 별도의 경계값을 가진다. 화면 폭 하나로 둘을 동시에 접거나, 단순히 모바일 메뉴를 숨기는 것으로 바꾸지 않는다.

## 네 가지 배치

| 카테고리 레일 | 상세 레일 | 스크롤 중 동작 |
|---|---|---|
| 옆 | 옆 | 두 레일과 상세 머리를 계속 표시한다. 불필요한 접힘이 없다. |
| 위 | 옆 | 카테고리의 프로젝트 목록이 이름 줄 밑으로 접힌다. 상세 머리의 돌아가기는 유지한다. |
| 옆 | 위 | 카테고리는 유지한다. 상세 머리가 접히고, 상단 현재 위치 바에 돌아가기가 남는다. |
| 위 | 위 | 이름·직무·테마 줄과 상세 현재 위치·돌아가기가 남는다. 큰 목록·상세 머리·하단 이동 줄은 읽는 공간을 확보하도록 접힌다. |

기준:

- 카테고리 레일: `max-width:680px` 또는 `max-aspect-ratio:5/4`에서 위로 이동.
- 상세 레일: 오른쪽 상세 컨테이너가 `820px` 이하일 때 위로 이동. 전체 브라우저 폭이 기준이 아니다.
- 상세 컨테이너가 `560px` 이하이면 더 작은 심볼과 간격을 사용한다.
- 이름과 직무의 기준선, 오른쪽 테마 버튼, 돌아가기의 접근성을 유지한다.

## 스크롤·탐색 규칙

- 아래로 읽으면 숨길 수 있는 부분만 접고, 위로 읽으면 다시 펼친다. 잠시 멈추면 읽던 방향으로 정돈한다.
- 텍스트 영역의 전체 높이는 고정한다. 앱바의 위치만 바꾸어 접힐 때 본문이 튀지 않게 한다.
- 문서 맨 위에서는 접히는 양이 스크롤 거리보다 크지 않다. 창 크기가 바뀌면 새 경계로 제한하고 앱바를 다시 보여 준다.
- 키보드 초점이 접힌 프로젝트 목록·상세 머리·하단 조작으로 이동하면 앱바를 펼쳐 초점이 가려지지 않게 한다.
- 넓은 상세 목차는 본문을 따라 현재 섹션을 표시하고, 누르면 해당 섹션으로 이동한다.
- 좁은 상세 바는 심볼·프로젝트·현재 섹션·돌아가기를 남기고 긴 목차는 숨긴다.
- 목차 이동은 현재 고정 영역 아래에 멈춘다. 움직임 줄이기 설정을 존중한다.
- 상세의 이전·다음 프로젝트 링크는 해당 프로젝트의 상세를 연다. 맨 위로 이동하는 조작도 제공한다.
- 같은 프로젝트의 상세를 열었다 닫을 때 뒤의 그림을 재마운트하지 않는다. 다른 프로젝트로 나갔다 돌아오는 것과 구별한다.
- 공유용 `/projects/<id>/` 주소도 대화형 환경에서는 홈의 같은 상세 화면으로 연결한다. JavaScript가 없으면 그 주소의 정적 상세 본문을 읽을 수 있다.

## 회귀 검수

실제 창 또는 같은 크기의 iframe 뷰포트에서 다음을 확인한다. CSS/단위 테스트 통과를 실제 화면 확인으로 대체하지 않는다.

1. 1440×668: 두 레일이 옆에 있고 읽어도 불필요하게 숨지 않는다.
2. 960×1080: 카테고리만 위로 오고, 충분히 긴 글을 읽으면 이름 줄과 상세 돌아가기가 남는다.
3. 1110×668: 카테고리는 옆, 상세만 위다. 상세 머리를 접어도 현재 위치·돌아가기가 보인다.
4. 390×844: 두 레일이 위로 오고, 스크롤 아래·위·맨 위에서 이름 줄·현재 위치·돌아가기가 가려지거나 겹치지 않는다.
5. 목차 이동, 이전·다음 프로젝트, 상세 닫기, 브라우저 뒤로 가기, 직접 상세 주소를 확인한다.
6. 밝음·어두움, 키보드, 움직임 줄이기, 긴 프로젝트명·섹션명을 확인한다.

긴 글이 필요하면 게시하지 않는 테스트 자료를 사용하고 원본 콘텐츠를 복원한 뒤 배포한다.

## 범위

이 문서의 동일성은 두 레일·고정 영역·읽기·탐색의 동작 기준이다. 원본의 프로젝트별 실험 카드·접기 묶음·타임라인 등은 원본 콘텐츠 데이터 구조에 의존한다. 이 템플릿의 `sections`는 일반 본문 목록이며 그런 내용을 임의로 만들어 복제하지 않는다. 실제 프로젝트에 작업 묶음이 필요하면 데이터·타입·검증·화면을 함께 확장하되 위 읽기 UX를 보존한다.
