# 아트 구현 레시피

이 문서는 표현 기법이다. 예시 값은 성능·모델·프로젝트의 사실이 아니다. 실제 데이터와 분리해 사용하고, [ART_STYLE.md](ART_STYLE.md)의 의미와 미감 기준을 함께 지킨다.

## 1. 코드의 경계와 확장 위치

현재 범용 렌더러는 `src/components/light-field.tsx`, 장식 장면은 `src/components/project-art.tsx`, 사이트 표면은 `src/app/globals.css`다. `light-field`의 `Scene`은 `(put, timeMs, width, height, dark)`를 받고, `put(x, y, size, brightness)`는 CSS 픽셀 기준이다.

새 의미 도식은 장식의 이름만 바꿔 재사용하지 않는다. 필요하면 `src/components/art/`에 장면, `src/lib/art/`에 공통 형상·선·카메라 유틸을 만든다. 이는 확장 위치 권장안이며 현재 그 폴더가 구현되었다는 뜻이 아니다.

역할을 분리한다:

1. **자료:** 공개 가능한 실제 입력·기록·조건. 장면이 임의로 수치를 만든다거나 런타임 난수로 측정치를 바꾸지 않는다.
2. **형상:** 고리·렌즈·기기·문서·분포 등 공유 가능한 의미 심볼.
3. **장면:** 형상 배치, 사건·전후·강조, 카메라.
4. **렌더:** 점·선·면의 빛과 잉크. 자료의 의미를 결정하지 않는다.
5. **오버레이:** 라벨·지시선·조작. 조작은 카메라 확대에 같이 빨려 들어가지 않는다.

원본 프로젝트의 비공개 규칙·상수·엔진을 복제하지 않는다. 이 레시피는 시각 표현만 다룬다.

## 2. 점광원 파이프라인

현재 렌더러의 순서:

```text
scene → 가산 밝기 버퍼 → 1/4 크기 축소 → 가로/세로 블러
      → 원 밝기 + 약한 glow → 테마별 밝기 색표 → 투명 바탕에 합성
```

- 점의 핵과 번짐을 분리한다. 몸통이 없는 흐린 얼룩만 남기지 않는다.
- 약한 영역은 바탕으로 사라진다. 캔버스 사각형의 색이 별도로 보이지 않아야 한다.
- 밝은 테마에서 투명 경계와 번짐이 회색 구름이 되지 않는지 확인한다.
- 점을 많이 겹치면 가산 밝기가 포화된다. 전체 알파를 올리기 전에 중복·밀도·주인공의 비율을 고친다.
- 테마 변화는 셰이더·바탕·라벨을 함께 갱신한다. 어두운 화면의 캡처에 색 반전 필터를 거는 방식으로 만들지 않는다.

### 기본 팔레트 예시와 교체

색은 `content/theme.json`이 유일한 원본이다. 아래는 출발점의 예시이며 고정 의무가 아니다. `scripts/theme.mjs`가 페이지의 CSS 변수와 그림의 GLSL 색을 같은 파일에서 생성한다. 사용자는 HEX 색만 바꾸면 된다. [THEME_GUIDE.md](THEME_GUIDE.md)를 읽는다.

어두운 화면의 RGB 기준점:

```text
INDIGO  (0.29, 0.21, 0.71)
MAGENTA (0.76, 0.13, 0.44)
ORANGE  (0.94, 0.40, 0.11)
AMBER   (1.00, 0.80, 0.29)
```

밝은 화면 flare 기준점:

```text
(0.929,0.689,0.504) → (0.907,0.494,0.390) → (0.838,0.308,0.372)
→ (0.666,0.227,0.430) → (0.479,0.180,0.437) → (0.294,0.137,0.384)
```

현재 선택한 정확한 코드값은 `content/theme.json`이 기준이다. 이 문서의 RGB는 원래 기본 팔레트를 설명하는 값이며 실제 렌더는 사용자가 고른 HEX에서 생성한다. 램프는 밝기용이며 이미지 원본색·일반 라벨을 일괄로 칠하는 용도가 아니다. `style-contract.json`은 연결과 구조를 검사하며 특정 팔레트를 잠그지 않는다.

### 선이 점보다 훨씬 밝아지는 문제

다른 렌더러를 확장할 때 선의 sRGB 변환과 밝기 lift를 중복 적용하지 않는다. 예를 들어 `c^0.72` 뒤에 sRGB 인코딩을 쓰는 선은 작은 수치도 크게 보인다. 수백 개의 옅은 선이 겹치면 의도보다 밝아진다. 주인공의 선·구조선·배경선의 합성 결과를 실제 테마에서 비교한다.

## 3. 잉크와 원본 색 파이프라인

신호 램프와 별도 장면 문법이다. 이미지 조각·토큰을 원본 RGB로, 구조와 처리기를 테마 잉크로 그린다. 밝은 화면은 일반 알파 합성, 어두운 화면은 필요에 따라 가산 합성을 사용하되 색 포화를 확인한다.

- 이미지의 전체 비율·방향과 조각이 어디서 왔는지를 유지한다.
- 입력이 세분화되면 각 조각이 제자리에서 나뉘고 대응 표현도 따라 변한다. 전체가 없어졌다가 다른 격자가 뜨는 일반 크로스페이드로 관계를 끊지 않는다.
- 처리기 내부의 모든 층을 실제 개수대로 그릴 필요는 없다. 반복 압축임을 제작 메모에 기록하고, 입력·출력·분기·적용 위치는 유지한다.
- 출력은 따로 떨어진 표보다 원래 축과 공간 안에 분포·선택·기둥으로 놓는 것이 맞는지 먼저 검토한다.
- 구조 전체가 필요한 장면과, 한 원인의 효과를 보여 주는 확대 장면을 구분한다. 모든 장면을 같은 넓은 샷으로 복사하지 않는다.

## 4. 재사용할 형상과 그 의미

| 대상 | 조형 방향 | 불변 요소 |
|---|---|---|
| 연속 입력 | 정돈된 선·리본·폭포형 신호 | 시간 방향·입력 구분 |
| 추론 출력 | 밀집된 분포 기둥·봉우리 | 출력 축·같은 값의 대응 위치 |
| 처리기 | 얇은 고리·렌즈·층과 가닥 | 실제 입출력과 핵심 분기 |
| 휴대 기기 | 일정 비율의 둥근 외곽·작은 틈 | 같은 외곽 원본·내부 부품 관계 |
| 문서 | 실제 비율의 종이·내용·필기 | 필기·서버 판정·원문 구분 |
| 결과량 | 대상에 붙은 빛 기둥·직접 값 | 단위·기준·전후의 같은 축 |

이는 이름을 바꿔 모든 분야에 덮어씌울 고정 목록이 아니다. 실제 프로젝트의 대상을 새로 등록할 수 있다. 데이터베이스·서버·로봇을 무조건 렌즈나 휴대폰으로 그리지 않는다.

심볼 레지스트리 기록 예:

```text
id: input-document
뜻: 사용자가 제출한 문서
원본: src/lib/art/document-outline.ts
불변: 외곽 비율, 접힌 모서리, 입력임을 나타내는 방향
변형: 크기, 테마 잉크, 활성 밝기
사용: 홈 장면, 상세의 과정, 작은 메뉴 표식
```

휴대 기기처럼 큰 장면과 작은 표식에 같이 쓰는 형상은 점 배열·경로 원본을 공유한다. 실제 폰 외곽의 권장 시작 비율은 폭/높이 약 0.48, 모서리 반지름은 폭의 약 0.16이다. 이는 조형 시작점이며 특정 기기의 실측 사양이 아니다.

작은 표식은 약 76~120px 폭에서도 먼저 확인한다. 복잡한 전체 장면을 줄이지 말고, 뜻을 남기는 윤곽과 핵심 입력·출력만 따로 정리한다.

## 5. 연결선과 지시선

[선 문법 도해](art/line-grammar.svg)를 참고한다. 실제 관계를 잇는 선과 라벨을 가리키는 선은 기하 문법을 공유한다.

정적 도해의 색은 기본 예시다. 실제 그림의 잉크·바탕·강조색은 사용자가 고른 테마 토큰을 따른다.

| 종류 | 시작 기준 | 시작 두께 | 움직임 | 끝점 |
|---|---|---|---|---|
| 데이터 | 잉크 | 1.5 CSS px | 의미가 있을 때 흐르는 빛 | 실제 입력·출력 |
| 지시선 | 약한 잉크 약 46% | 1 CSS px | 정지 | 대상 위 약 2px 점, 라벨 옆 짧은 착지 |
| 지시선의 바탕 테 | 무대색 | 약 4 CSS px | 없음 | 선과 글이 읽히게 뒤에서 분리 |

수평·수직·45° 구간을 잇고 모서리만 둥글게 만든다. 초기 꺾임 반경은 데이터 12px, 지시선 6px, 라벨 착지는 약 12px다. 역할 안에서는 동일한 반경을 사용하고 짧은 구간이면 인접 길이의 절반 이하로 줄인다. 크기를 바꿀 때 전역 스케일로 조절한다.

화면 좌표에서 시작점 A와 끝점 B의 `dx`, `dy`를 구한다. 긴 축 구간 → 45° 구간 → 긴 축 구간으로 라우팅한다. 짧은 축 차이가 `max(6px, 긴 축의 10%)`보다 작으면 작은 계단을 만들지 않고 정렬 가능한 수평·수직 구간으로 편다. 실제 포트에 접점이 남는지도 확인한다.

라벨 지시선은 대상에서 한 사선 뒤 평평한 착지로 연결하는 것을 우선한다. 라벨 간 교차·대상 관통·짧은 반복 꺾임이 생기면 라우팅 알고리즘보다 라벨 배치를 먼저 고친다. 파형·고리·실제 곡면은 연결선이 아니므로 본래 곡선을 유지한다.

### 3D 대상과 2D 라벨을 붙이는 순서

```text
이번 프레임의 장면 시간과 카메라 갱신
→ 대상의 local 좌표를 world 좌표로 변환
→ 동일 카메라로 NDC 투영
→ 그림 칸의 CSS 픽셀로 변환
→ 라벨과 선의 접점·착지 위치를 함께 배치
→ 한 SVG 오버레이에 경로와 대상 점 표시
```

카메라와 라벨을 다른 프레임·다른 좌표 원점에서 계산하지 않는다. 포인터 시차·리사이즈·스크롤·전환 도중에도 같은 대상에 붙는지 확인한다. `devicePixelRatio`를 라벨 CSS 좌표에 한 번 더 곱하지 않는다.

## 6. 카메라 구도와 화면 맞춤

- 단순한 원근·가림·겹침으로 앞뒤를 읽게 한다. 점 개수를 늘리는 것으로 입체감을 대신하지 않는다.
- 장면의 핵심 bounding points를 카메라에 투영해 실제 상자의 종횡비에 맞춘다. 제목과 조작이 사용한 공간을 빼고 그림 공간을 계산한다.
- 큰 화면에서 좋았던 구도는 보존한다. 모바일 수정은 별도 조건에서 카메라 거리·타깃·라벨 배치를 고친다.
- 낮은 창에서는 중복 머리말과 여백을 먼저 줄인다. 주인공을 축소해 전부 우겨 넣지 않는다.
- 직접 비교하는 값은 같은 카메라·축·눈금에 둔다. 원근으로 전후의 크기를 왜곡하지 않는다.
- 전환 전후의 공유 대상은 중심만 맞추지 말고 앞·뒤·좌·우 등 기준점을 투영해 크기·기울기까지 맞춘다. 둥근 대상이면 타원의 중심·가로/세로 반경이 기준이 된다.

## 7. 동일 대상이 이어지는 전환

실제 포함 관계가 있을 때만 사용한다. 예: 전체 제품에서 내부 모듈로 들어가기. 다음은 확장 시의 순서이며 현재 템플릿이 이 전환을 모두 구현했다는 뜻이 아니다.

1. 다음 장면을 같은 페이지 사각형에 겹쳐 놓고, 보이지 않는 상태에서 렌더링 준비를 한다.
2. 대상의 등장 애니메이션이 있으면 목표 상태를 정한 뒤 접점을 읽는다. 움직이는 중간 레이아웃을 최종 위치로 저장하지 않는다.
3. 이전 장면의 카메라를 공유 대상에 맞춰 이동시킨다. 나머지 구조는 같은 자리로 접히거나 약해진다.
4. 준비·착지 이벤트를 확인한 뒤 짧게 교차한다. 느린 장치에서 고정 시간만 기다려 미완성 상태로 바꾸지 않는다.
5. 이전 장면이 실제로 숨겨진 뒤 임시 fixed·크기·opacity를 해제한다. 중간에 레이아웃이 튀지 않게 한다.
6. 공유 대상이 없거나 준비가 실패하면 일반 전환으로 복귀한다. 수정키 클릭·새 탭·뒤로 가기·움직임 줄이기는 정상 링크로 동작한다.

움직임의 시작점은 의미 있는 부품이다. 화면 가운데를 향한 임의의 줌을 모든 메뉴에 적용하지 않는다. 완료 전에는 겹치는 라벨을 숨기고, 안정된 뒤 자연스럽게 읽히게 한다.

### 전환 중 버튼이 사라지는 함정

`getBoundingClientRect()`는 CSS transform이 반영된 값이다. 등장 애니메이션의 축소 상태에서 버튼의 기준 높이를 한 번 측정해 저장하면 버튼이 화면 밖에 고정될 수 있다. 고정 UI의 배치는 변형되지 않은 layout 좌표(`offsetTop`/`offsetParent` 등)로 측정하거나 변형을 분리한다. 반대로 두 그림 사이의 실제 착지에는 화면에 투영된 값이 필요하다. 두 목적을 혼동하지 않는다.

## 8. 시간·시차·신호 정돈

부드러운 포인터 반응의 시작식:

```text
dt = min(0.1, 이번 프레임과 이전 프레임의 초 차이)
k = 1 - exp(-3.2 * dt)
lean += (pointerTarget - lean) * k
```

프레임별 상수만 더해 기기마다 속도가 달라지게 하지 않는다. 터치 포인터는 카메라 반응에서 제외하고, 움직임 줄이기에서는 대표 정지 구도를 사용한다. 라벨은 같은 시차 카메라를 따른다.

실제 데이터를 사용할 때 사건 시간과 의미는 기록에 맞춘다. 표시만 정돈한다: 더 적은 대표 입자, 핵심 사건 단위, 짧은 시간 평활, 한 사건씩 확정 표시, 화면 안에 머무는 경계. 빠르게 바뀌는 원시 수치 전부를 주인공으로 만들지 않는다. 적용한 평활·추출은 제작 메모에 기록한다.

루프 경계는 새 시작이다. 이전 바퀴의 시간 창·잔상·확정 핀·이벤트·차분이 넘어가지 않게 한다. 경계 앞·뒤와 초기 진입을 따로 본다. 정지 캡처만으로 지터·중복 재생·경계 오류를 통과 처리하지 않는다.

## 9. 성능·정리·대체

- 선택된 장면만 렌더링하고 화면 밖·백그라운드에서는 작업을 줄인다. 큰 버퍼는 재사용하고 프레임마다 물체·배열·DOM을 대량 생성하지 않는다.
- 현재 렌더러의 DPR 상한은 2, 점 버퍼 상한은 9000이다. 개별 장면이 늘어도 버퍼 한도를 묵시적으로 넘기지 않는다.
- 해제 시 rAF, observer, 이벤트, shader program, buffer, texture, framebuffer를 정리한다. React StrictMode 재실행을 확인한다.
- 같은 캔버스에서 강제로 컨텍스트를 잃게 하는 정리 방식은 재마운트에서 실패할 수 있다. 일반 자원을 정리하고 실제 브라우저에서 재진입을 확인한다.
- float framebuffer 지원을 확인하고 하위 형식으로 복귀한다. 셰이더·프레임버퍼 실패도 가능한 경우 대체 표현으로 처리한다.
- 대체 그림은 장면의 뜻과 링크를 유지한다. 장식은 간단한 윤곽이어도 되지만, 의미 있는 도식의 대체가 아무 뜻 없는 로딩 상자여서는 안 된다.
- 렌더러나 색표를 바꿀 때는 해당 기술의 현재 공식 문서를 확인한다. 외부 라이브러리는 필요할 때만 추가하고 라이선스를 보존한다.
