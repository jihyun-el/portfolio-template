# Portfolio Template

**내 이야기는 내가 답하고, 웹 작업은 에이전트에게 맡기는 포트폴리오 템플릿입니다.**

웹을 처음 접하는 사람도 사용할 수 있도록 만들었습니다. 코딩 에이전트가 질문을 통해 경험을 정리하고, 답을 사이트에 반영합니다. 개발 경험이 많지 않아도 수업 과제, 팀 프로젝트, 작은 도구부터 시작할 수 있습니다.

샘플의 이름·프로젝트는 입력 안내용입니다. 실제 개인의 경력·성과·커밋 기록을 포함하지 않습니다. 왼쪽 메뉴와 오른쪽 프로젝트 화면, 밝은/어두운 테마, 빛으로 그린 추상 그래픽이 들어 있습니다.

## 1. 내 저장소로 복사하기

이 저장소 위쪽의 **Use this template → Create a new repository**를 누릅니다. 저장소 이름은 `my-portfolio`처럼 정하면 됩니다. 무료 GitHub Pages로 공개하려면 Public으로 만드세요.

새 저장소를 코딩 에이전트에서 여세요. Codex, Claude Code, Cursor, GitHub Copilot 등에 아래 요청문을 그대로 붙여 넣으면 됩니다. 사용 중인 도구에서 저장소 폴더에 접근할 수 있어야 합니다.

```text
이 저장소의 AGENTS.md를 끝까지 읽고, 규정된 응답 형식과 인터뷰 절차를 따라 줘.
나는 웹 개발을 잘 모르고 이 템플릿으로 내 포트폴리오를 만들고 싶어.
내 프로젝트와 직접 한 일을 구체적으로 캐물어 줘. 답이 추상적이면 후속 질문을 해 줘.
내가 모르는 내용은 만들어 내지 말고, 확인된 사실만 공개할 글로 정리해 줘.
디자인과 아트 규칙은 유지하고, 내가 답한 내용을 사이트에 반영해 줘.
처음에는 확인한 내용 / 이번 질문 / 다음 작업 순서로 답해 줘.
```

에이전트가 이름, 관심 분야, 프로젝트, 직접 한 일, 막혔던 점 등을 질문합니다. 평소 말하듯 답하면 됩니다. "모르겠어요", "이건 공개하지 않을래요", "여기까지만 묻고 만들어 주세요"라고 말해도 됩니다. 이미 있는 README나 발표 자료를 주면 도움이 되지만 필수는 아닙니다.

## 2. 확인하고 고치기

만든 화면을 보고 구체적으로 말해 주세요.

```text
미리보기를 열어 줘. 휴대폰에서도 확인해 줘.
첫 번째 프로젝트에서 로그인은 팀원이 했고, 나는 검색 기능을 맡았어. 그 부분을 고쳐 줘.
수치는 측정한 적이 없으니 빼고, 실제로 동작하는 기능을 설명해 줘.
```

주요 내용은 `content/portfolio.json` 하나에 있습니다. 에이전트가 이 파일을 수정합니다. 직접 수정하고 싶다면 [콘텐츠 안내](docs/CONTENT_GUIDE.md)를 보세요.

## 3. 내 주소로 배포하기

새 저장소에서 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 한 번 선택합니다. 저장소 소유자 권한이 필요합니다.

에이전트에게 다음처럼 요청하세요.

```text
이제 내 GitHub 저장소에 공개 배포해 줘.
원격 저장소가 내 저장소인지 확인하고, 테스트·빌드·타입 검사와 개인정보 점검을 해 줘.
GitHub Pages 설정도 확인하고, 완료되면 실제 접속되는 사이트 주소를 알려 줘.
```

권한 때문에 에이전트가 Pages 설정을 바꾸지 못하면 위 메뉴에서 직접 선택하면 됩니다. 이어서 **Actions → Deploy portfolio to GitHub Pages → Run workflow**를 누르거나 `main`에 변경을 올리면 배포됩니다. 처음 복사한 저장소에 Actions 허용 버튼이 보이면 활성화하세요. 저장소 이름에 따른 사이트 경로는 자동으로 설정됩니다.

완료 후 주소는 보통 `https://내계정.github.io/내저장소/`입니다. 저장소 이름이 `내계정.github.io`이면 루트 주소로 배포됩니다. 별도 도메인을 설정한 경우에는 Pages 설정의 주소를 사용합니다. [GitHub의 Pages 설정 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)에서 메뉴를 확인할 수 있습니다.

## 자주 묻는 것

- **프로젝트가 하나뿐인데 괜찮나요?** 하나만 남겨도 됩니다. 프로젝트가 없는 상태도 동작합니다.
- **경력이나 수상이 없어요.** 빈 목록으로 두면 됩니다. 없는 내용을 채울 필요가 없습니다.
- **팀 프로젝트인데요?** 팀이 만든 것과 내가 맡은 것을 나누어 답해 주세요.
- **AI로 만들었는데요?** AI에게 맡긴 부분, 직접 결정한 부분, 실행해 검증한 부분을 말해 주세요.
- **사진이 꼭 필요한가요?** 없어도 추상 그래픽으로 표시됩니다. 화면 캡처를 쓰려면 에이전트에게 파일을 주고 교체를 요청하세요.
- **마음에 안 드는 그림이 있어요.** `orbit`, `layers`, `flow`, `none` 중 고르거나, 프로젝트에 맞는 실제 도식을 요청하세요.
- **질문이 많아요.** 경험을 지어내지 않고 구체적인 글을 쓰기 위한 질문입니다. "나머지는 빼고 여기까지로 만들어 주세요"라고 하면 됩니다.
- **내용을 고친 뒤 다시 배포하려면요?** `main`에 올리면 자동으로 다시 배포됩니다. 에이전트에게 수정과 배포를 함께 부탁해도 됩니다.
- **내 자료가 모두 공개되나요?** `content/`와 공개 파일에 반영한 내용은 공개됩니다. 공개하면 안 되는 정보는 인터뷰 중 미리 말해 주세요. 인터뷰 메모용 `private/`는 Git에서 제외됩니다.

## 개발용 실행

Node.js 24 권장. Next.js의 정적 내보내기를 사용하며, 별도 서버나 데이터베이스가 필요하지 않습니다.

```sh
npm ci --ignore-scripts
npm run dev
npm test
npm run build
npm run check-types
npm run preview
```

개발 주소는 `http://127.0.0.1:3000`, 빌드 결과 미리보기는 `http://127.0.0.1:4173`입니다. 빌드 결과는 `out/`에 생성됩니다. 저장소 경로를 붙여 검증하는 법은 [콘텐츠 안내](docs/CONTENT_GUIDE.md)에 있습니다.

- [에이전트 작업 규약](AGENTS.md): 질문 방식, 응답 형식, 사실 확인, 검증·배포
- [디자인과 아트 규칙](docs/ART_DIRECTION.md): 레이아웃, 색, 타이포그래피, 빛 표현
- [콘텐츠 안내](docs/CONTENT_GUIDE.md): JSON 필드, 이미지, 링크, 빈 목록

에이전트의 지침 준수 정도는 사용하는 도구와 모델에 따라 달라집니다. 첫 요청에 `AGENTS.md`를 읽으라고 명시하고, 작성된 내용이 실제 경험과 맞는지 확인해 주세요.
